01 De un commit a producciónFrom a commit to production

Recorrido completo de un cambio de código, desde el commit hasta su operación en producción, con las herramientas que intervienen en cada fase. Es el modelo de entrega que implanto en cualquier equipo: automatizado de extremo a extremo, con identidades de mínimo privilegio y sin intervención manual sobre los entornos. El punto que recorre el diagrama representa el commit. The full journey of a code change, from commit to production operations, with the tools involved at each stage. It is the delivery model I put in place in any team: automated end to end, with least-privilege identities and no manual intervention on the environments. 04 Caso realCase study: fixcomap/platform

Una plataforma interna, operativa y de código abierto, que construí junto a mi hermano para fixcomap: infraestructura en Google Cloud y Cloudflare gestionada con OpenTofu, un catálogo de proyectos y un único pipeline que usan todos los repositorios. Dar de alta una aplicación nueva es añadir un fichero YAML; esta misma página se publica a través de ella. Coste de explotación mensual: el dominio. An internal, working, open-source platform I built with my brother for fixcomap: Google Cloud and Cloudflare infrastructure managed with OpenTofu, a project catalogue and a single pipeline shared by every repository. Onboarding a new application means adding one YAML file; this very page is published through it. Monthly operating cost: the domain.

El catálogo como única fuenteThe catalogue as single source of truth

Cada proyecto se describe en catalog/<repo>.yaml: tipo, dominios, front, migraciones y secretos. El pipeline, los dominios, el monitoreo y los permisos se derivan de ahí; un repositorio sin entrada no despliega nada.Each project is described in catalog/<repo>.yaml: type, domains, front end, migrations and secrets. Pipeline, domains, monitoring and permissions are all derived from it; a repository without an entry deploys nothing.

Un pipeline versionado para todosOne versioned pipeline for everyone

Los repositorios no mantienen pipeline propio: fijan cicd.yml@vX.Y.Z y un router decide si es un sitio estático o una webapp. Una mejora llega a cada proyecto de forma controlada, con una PR de una línea.Repositories keep no pipeline of their own: they pin cicd.yml@vX.Y.Z and a router decides whether it is a static site or a web app. An improvement reaches each project in a controlled way, through a one-line PR.

Una identidad por aplicaciónOne identity per application

GitHub Actions entra en Google Cloud por OIDC, sin claves. Cada webapp despliega con su propia cuenta <app>-deployer, que solo alcanza sus servicios, su estado y sus secretos; los cambios de IAM se aplican tras revisar el plan.GitHub Actions reaches Google Cloud through OIDC, with no keys. Each web app deploys with its own <app>-deployer account, scoped to its own services, state and secrets; IAM changes are applied only after the plan is reviewed.

05 Estándar de seguridad y calidadSecurity & quality standard

Lo que se exige a todas las aplicaciones, sin excepciones. Se define una vez en la plataforma y llega a toda la organización: si una mejora no se puede aplicar a todas, no se aplica a ninguna. What every application must meet, no exceptions. It is defined once in the platform and reaches the whole organisation: if an improvement cannot apply to every app, it applies to none.

En cada pull requestOn every pull request

  • CodeQL obligatorio en los rulesets: una alerta nueva bloquea el mergeCodeQL required by rulesets: a new alert blocks the merge
  • gitleaks, trivy (código, IaC e imágenes), checkov, tflint y actionlintgitleaks, trivy (code, IaC and images), checkov, tflint and actionlint
  • Lint y tests obligatorios en cada paquete; un paquete sin ellos no pasaMandatory lint and tests in every package; a package without them fails

Tests contra una base realTests against a real database

  • Tests de integración que recorren la API de verdad: altas, permisos, conflictosIntegration tests that drive the real API: sign-ups, permissions, conflicts
  • Pasarelas externas simuladas: webhook de pago con firma válida e inválida, reembolsosSimulated third parties: payment webhook with valid and invalid signatures, refunds
